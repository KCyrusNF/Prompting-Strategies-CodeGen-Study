def rotate_list(nums, k):
    # Step 1: Handle the edge case of an empty list
    if not nums:
        return nums
    
    # Step 2: Normalize k by taking k modulo the length of the list
    n = len(nums)
    k = k % n  # This ensures that k is within the bounds of the list length
    
    # Step 3: Calculate the split point
    split_point = n - k
    
    # Step 4: Slice the list into two parts
    last_k_elements = nums[-k:]   # Last k elements
    first_part = nums[:split_point]  # First (length - k) elements
    
    # Step 5: Concatenate the slices and return the result
    return last_k_elements + first_part

Explanation:

Edge Case: If nums is an empty list, return it immediately.

Normalize k: Since rotating a list by its length doesn't change the list, we use k % n to reduce the number of rotations to a manageable value.

Split Point: The split_point is calculated as n - k to figure out where the list should be divided for the rotation.

Slicing: We slice the list into the last k elements (nums[-k:]) and the first (n - k) elements (nums[:split_point]).

Concatenate: We concatenate the last k elements with the first part of the list and return the result.

Example Usage:
# Example 1:
nums = [1, 2, 3, 4, 5]
k = 2
print(rotate_list(nums, k))  # Output: [4, 5, 1, 2, 3]

# Example 2:
nums = [1, 2, 3]
k = 7
print(rotate_list(nums, k))  # Output: [3, 1, 2]

# Example 3:
nums = [1, 2, 3, 4]
k = 0
print(rotate_list(nums, k))  # Output: [1, 2, 3, 4]

# Example 4:
nums = []
k = 3
print(rotate_list(nums, k))  # Output: []

Time Complexity:

Time Complexity: O(n), where n is the length of the list. This is because slicing the list and concatenating takes linear time in the size of the list.

Space Complexity: O(n), because we are creating new slices and concatenating them.
